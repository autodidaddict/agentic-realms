# Data Model: Player Authentication & Account Management

**Feature**: 002-user-auth  
**Date**: 2026-04-23

## Entities

### Player

The sole persistent entity for this feature. Represents a registered user account.

**Fields**:

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| id | integer (auto) | Primary key | Auto-generated by database |
| username | string | Not null, unique, 3-30 chars, alphanumeric + hyphens + underscores | Used for login and display |
| hashed_password | string | Not null | bcrypt hash; plaintext never stored |
| inserted_at | utc_datetime | Not null | Auto-set by Ecto timestamps |
| updated_at | utc_datetime | Not null | Auto-set by Ecto timestamps |

**Validation Rules**:
- `username`: required, unique (database-level unique index), format `~r/^[a-zA-Z0-9_-]+$/`, length 3..30
- `password` (virtual field, not persisted): required on registration, minimum 8 characters
- `hashed_password`: generated from password via bcrypt; never set directly

**Indexes**:
- Unique index on `username` (for login lookups and uniqueness enforcement)

### Session (non-persistent)

Session state is stored in the browser cookie via `Plug.Session`. Not an Ecto entity.

**Session keys**:

| Key | Type | Notes |
|-----|------|-------|
| player_id | integer | ID of the authenticated player; set on login, cleared on logout |

**Lifecycle**:
- Created on successful login or registration (player ID stored in session)
- Destroyed on logout (session cleared) or account deletion (session cleared + player removed)
- Lost on server crash (acceptable per user requirements)
- No expiration configured beyond browser session (cookie expires when browser closes)

## Relationships

No relationships between entities in this feature. The Player entity is standalone. Future features (game state, character data) may create associations from other entities to Player.

## State Transitions

### Player Account Lifecycle

```
[Visitor] --register--> [Active Player] --delete--> [Removed]
                              |
                         update username
                         update password
```

- **Visitor → Active Player**: Registration creates the Player record, logs them in
- **Active Player → Active Player**: Profile updates (username, password) modify the existing record
- **Active Player → Removed**: Account deletion permanently removes the Player record from the database; session is cleared

### Session Lifecycle

```
[No Session] --login/register--> [Active Session] --logout/delete--> [No Session]
                                       |
                                  [Server Crash] --> [No Session]
```
